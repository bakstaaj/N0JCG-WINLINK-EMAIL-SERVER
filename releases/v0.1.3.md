# N0JCG Winlink Email Server v0.1.3

Packet RMS session reliability, mailbox progress, and operator guidance release.

## Highlights

- Added one-user-at-a-time RF session control: a new login stops any previous Pat/AGW session and allows a ten-second RF/PTT settle period.
- Increased the on-demand Packet RMS login wait to 180 seconds for real-world RF retries while preserving the separate mailbox-transfer timeout.
- Added progressive mailbox status messages for RMS connection, secure login, mailbox index, proposals, message selection, downloads, and clean finalization.
- Preserved the authenticated webmail session after post-authentication transfer failures so the user can review the result and retry without exposing mailbox data.
- Disabled Refresh during an active mailbox transfer and hardened completion handling when the RMS closes after message delivery.
- Corrected operator diagnostics to report the actual Dire Wolf and AGW bridge services and on-demand Pat behavior.
- Kept AGWPE identity mapping dynamic for the logged-in Winlink callsign; no mailbox or RF frames are hard-coded to N0JCG.
- Updated the N0JCG-branded end-user guide with the new session, progress, recovery, and local-versus-CMS mailbox behavior, with current operator and webmail screenshots.

## Validation

- Python unit tests pass, including webmail session, progress, identity-bridge, and mailbox-state coverage.
- Appliance schema and safety validation pass.
- DOCX and PDF manuals were rebuilt and rendered for visual QA.
- Release ZIP contents were inspected and contain no credentials, `.env` files, or transient runtime folders.
- The official Winlink client transport remains the supported Packet RMS client path.

## Hardware boundary

This remains a client-side appliance, not an RMS gateway. Radio, DigiRig Mobile, packet modem, PTT, and RF operation require compatible hardware, operator commissioning, and local verification.
